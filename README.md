# Microservices Architecture Project

This project implements a modular system using microservices for product management and order processing. The project demonstrates various software design principles, such as separation of concerns, asynchronous messaging, error handling, and secure API communication.

## Project Structure

```plaintext
/microservices/
├── /instances/                    # Databases for each microservice
│   ├── orders.db                  # Database for the order service
│   ├── products.db                # Database for the product service
│
├── /orders_service/               # Order management service
│   ├── app.py                     # Main application logic
│   ├── models.py                  # Database models
│   ├── services.py                # Business logic and messaging
│   ├── auth.py                    # Authentication handling
│   ├── .env                       # Environment configuration
│   └── requirements.txt           # Service dependencies
│
├── /products_service/             # Product management service
│   ├── app.py                     # Main application logic
│   ├── models.py                  # Database models
│   ├── auth.py                    # Authentication handling
│   ├── .env                       # Environment configuration
│   └── requirements.txt           # Service dependencies
│
├── /messaging/                    # Messaging for RabbitMQ
│   ├── producer.py                # Message producer
│   ├── consumer.py                # Message consumer
│   └── requirements.txt           # Dependencies
│
└── .gitignore                     # Ignoring sensitive files
```

## Prerequisites

1. **Python**: Install Python 3.8 or higher.
2. **RabbitMQ**: Ensure RabbitMQ is installed and running.
3. **Environment Configuration**: Set environment variables in each service’s `.env` file.
4. **Postman** or similar tool for testing endpoints.

## Installation

1. Clone the repository:

   ```bash
   git clone <repo-url>
   cd microservices
   ```

2. Create virtual environments for each service:

   ```bash
   python3 -m venv orders_service/.venv
   python3 -m venv products_service/.venv
   python3 -m venv messaging/.venv
   ```

3. Install dependencies for each service:

   ```bash
   source orders_service/.venv/bin/activate
   pip install -r orders_service/requirements.txt
   deactivate

   source products_service/.venv/bin/activate
   pip install -r products_service/requirements.txt
   deactivate

   source messaging/.venv/bin/activate
   pip install -r messaging/requirements.txt
   deactivate
   ```

## Services

### Products Service
Handles the product catalog, including adding, updating, and retrieving product details.

- **Base URL**: `http://localhost:5001`

Endpoints:
- `GET /products`: Retrieve all products.
- `POST /products`: Add a new product.
- `GET /products/<id>`: Retrieve a specific product by ID.

### Orders Service
Manages customer orders and processes them asynchronously through RabbitMQ.

- **Base URL**: `http://localhost:5002`

Endpoints:
- `POST /orders`: Place a new order.
- **JWT Required** for secured endpoints.

### Messaging
Handles asynchronous communication between services using RabbitMQ, ensuring reliable and decoupled service interactions.

## Security

Each service requires a JWT for secure access. Tokens are generated by sending valid credentials to the `/login` endpoint (part of `auth.py`). Use `.env` files to store sensitive information like the JWT secret and database credentials.

## Running the Project

1. **Start RabbitMQ**:

   ```bash
   sudo systemctl start rabbitmq-server
   ```

2. **Run Services**:

   ```bash
   # Start Products Service
   cd products_service
   source .venv/bin/activate
   python app.py

   # Start Orders Service
   cd ../orders_service
   source .venv/bin/activate
   python app.py

   # Start Messaging
   cd ../messaging
   source .venv/bin/activate
   python consumer.py  # Starts the message consumer
   ```

## API Documentation

API contracts are defined in an OpenAPI-compliant `api_contracts.yml` file. This file can be imported into tools like [Swagger](https://swagger.io/tools/swagger-editor/) or [Postman](https://www.postman.com/) for better visualization and testing.

## Testing

Use **Postman** to test the APIs by creating requests to the product and order services. Ensure you:
1. Obtain a JWT token from the `/login` endpoint.
2. Use this token in the `Authorization` header for secured routes.

## Troubleshooting

- **Database Connection Issues**: Ensure paths are correctly set in `.env` files.
- **RabbitMQ Connection Errors**: Verify RabbitMQ is running and accessible.
- **JWT Authentication Failures**: Confirm credentials in `.env` match login requests.
